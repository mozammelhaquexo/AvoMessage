### Vercel — not yet deployable, and why
- `vercel` CLI is **logged out**; `vercel login` prints a device code
  (`https://vercel.com/oauth/device?user_code=…`) and polls. Waiting on the user.
- **Architecture mismatch:** the app ships a custom server (`server.ts`, Next +
  Socket.io on one port), an **embedded Postgres**, and `STORAGE_DRIVER=local`
  disk uploads. Vercel is serverless: no long-running server, no local DB, no
  persistent disk. Auth/pages/API would work; **realtime chat, calls and uploads
  would not**. A hosted Postgres (Neon/Supabase) is also required.
- A local `npm run build` while `npm run dev` was live **deadlocks** — both own
  `.next/`. Also `/tmp` is shared with other WorkBuddy sessions; two sessions
  writing `/tmp/build2.log` collided. Use unique log paths.
- User's decision: keep chat, **delete the audio-call feature**, and they will
  log in to Vercel via Chrome.
