## The `cn()` bug: 37 call sites silently losing their font-size

Mozammel bhai asked for two cosmetic changes: the "Super Admin" / "Manager" chip inside a
post was too big, and the gaps between the post action-bar icons were too wide. The first
one turned out not to be a taste problem.

### What was actually wrong

`cn()` is `twMerge(clsx(...))`. tailwind-merge only knows Tailwind's *built-in* scale, and
this project declares its own in `app/globals.css` (`@theme`): display, h1, h2, h3, body-sm,
caption, tiny. An unrecognised `text-*` token is classified as a text **colour**, so
combining a size with a colour kept only the last one:

```
twMerge('text-tiny',   'text-amber-700')  =>  'text-amber-700'
twMerge('text-caption','text-ink-3')      =>  'text-ink-3'
twMerge('text-body-sm','text-ink')        =>  'text-ink'
twMerge('text-h2',     'text-ink')        =>  'text-ink'
twMerge('text-sm',     'text-amber-700')  =>  'text-sm text-amber-700'   // built-in: fine
```

No warning, no error. The class left the DOM, nothing set a font-size, and the element fell
back to the browser default **16px**.

Measured on the live deployment before the fix:

| | before | after |
|---|---|---|
| chip font-size | **16px** | 11px |
| chip vs author name | **1.14× (bigger than the name)** | 0.79× |
| chip box | 127.8 × 18 px | 104.6 × 15 px |
| action-bar gap | **76.4 / 76.5 / 76.5 / 76.5 px** | 4 / 4 / 4 / 4 px |

The action-bar gap was arithmetic, not opinion: `justify-between` on a 566px bar with 260.2px
of content leaves 305.8px to spread over 4 gaps = 76.45px each.

### The fix

`components/ui/utils.ts` now calls `extendTailwindMerge` and registers the project's type
scale in the `font-size` class group. One change, all 37 sites. `extend` (not `override`)
keeps Tailwind's built-ins working, and genuine conflicts (`text-tiny + text-caption`) still
resolve to the last one.

`tests/cn-type-scale.test.ts` guards it in two layers: the exact merge shapes that broke, plus
a sweep of every `cn()` call in `components/`, `app/` and `lib/`. The sweep had to learn two
things the hard way, both now commented in the test:

- **The size usually lives in a shared constant.** `CHIP` holds `text-tiny`; the colour is
  written inline at the call site. A sweep that reads only the literals inside `cn(...)` sees
  the colour and never the size, and reports a cheerful zero.
- **Ternary branches are alternatives, not co-occurring.** `compact ? "text-body-sm" :
  "text-h3"` produced false positives on three files until the sweep was made to expand the
  call into its real combinations.

Proved the test bites: reverting the `cn()` config to `text: []` fails 3 of 6 tests and lists
the offenders. Restoring it passes.

### Scope warning worth remembering

This was **not** a chip bug. 37 `cn()` calls across 25 files were rendering at 16px instead of
their intended size — Sidebar, DataTable, MessageBubble, CommentThread, Card, Select, form
fields, the toasts, `app/(app)/settings/page.tsx`. Those all shrink to their written size as a
result. Correct, but it is a wide visual change, not a local one.

### Deliberate design choices

- Chip is now `text-tiny` (11px) + `uppercase tracking-wide font-semibold leading-none`
  with a 10px glyph. Uppercase because at 11px a role label reads better as a label.
  CompanyBadge stays sentence case — a company name is a proper noun, not a role.
- Action bar moved from `justify-between` to `justify-start gap-1`. This leaves the right side
  of the row empty. Flagged to the user as a taste call with the alternative (3 left / 2 right)
  offered.

### Environment notes found on the way

- `npm start` **does not work on Windows**: the script is `NODE_ENV=production tsx server.ts`
  and cmd.exe has no inline env-var syntax. Same for `start:compiled`. Local production runs
  need `NODE_ENV=production npx tsx server.ts` by hand. Vercel is unaffected.
- `next build` fails under the agent harness with `SAFE_DELETE_BULK_CONFIRM_REQUIRED` when it
  tries to clear `.next/turbopack` (50 files). Workaround: `mv .next .next.bak` first, then
  build fresh. Deleting `.next.bak` afterwards takes many minutes — the shim trashes files one
  at a time.
- A **CSRF header is required** for any mutating `/api/*` call outside the app: read the
  `avo_csrf` cookie and echo it as `x-csrf-token` (`lib/auth/csrf.ts`). Playwright's
  `ctx.request` shares cookies but does not add that header, so `POST /api/posts` returns 403
  `CSRF_INVALID` until you set it.
- The local dev server (`tsx server.ts`) does **not** hydrate the feed in a headless browser —
  the HMR websocket fails and `PostFeed` never fires `GET /api/posts`, so `/home` renders an
  empty shell. Measure against a local production build instead.
